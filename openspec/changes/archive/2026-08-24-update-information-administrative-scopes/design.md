## Context

当前前端将通用图片接口封装在 `imageApi` 中，并通过 `city:*`、`county:*` 与 `visited:*` 标签把图片记录映射为足迹。市级和区县级状态共用同一个面板，但面板始终开放创建、编辑和删除。省级地图会阻止直辖市区县选择。

最新图片服务使用 `/api/information/*` 路径，列表和元数据提供 `provinceCode`、`cityCode`、`districtCode` 等结构化字段；上传接口允许三级行政区字段缺省，更新接口不接受行政区字段。具体行为目标见 `proposal.md` 与本变更的规格增量。

## Goals / Non-Goals

**Goals:**

- 让页面层级、查询条件、上传归属和可用操作由同一个类型化行政区上下文驱动。
- 隔离 API 契约、足迹领域映射、面板状态和地图选择，使每一层可以独立测试。
- 保持现有普通省份的省、市、区县导航结构，同时让直辖市直接选择区县。
- 在请求或单张图片详情失败时保持可恢复且不误导用户的界面状态。

**Non-Goals:**

- 不把前端操作能力当作后端安全权限，也不增加登录或鉴权。
- 不迁移行政区字段为空的历史记录。
- 不实现图片懒加载、压缩、大小限制或缓存优化。
- 不为港澳台及其他缺少可下钻数据的地区补充信息创建流程。
- 不为直辖市增加虚拟市级编码、同名中间页面或新的区县路由。

## Decisions

### 使用判别联合表示可查询行政区上下文

信息层只接收两种上下文：市级上下文包含 `provinceCode`、`cityCode`、名称和禁止创建的能力；区县上下文包含 `provinceCode`、可选 `cityCode`、`districtCode`、名称和完整增删改能力。省级页面没有信息上下文，因此不会实例化加载器或调用信息接口。

该模型让查询条件、上传字段和按钮可见性由同一对象派生，避免页面分别判断层级后产生不一致。相比保留现有 `level + code` 并在各调用点补充父级编码，判别联合可以在类型层阻止区县上传缺少 `districtCode`，也能自然表达直辖市没有 `cityCode`。

### 用结构化字段查询和保存归属

市级列表发送 `{ cityCode, page, size }`，区县列表发送 `{ districtCode, page, size }`。普通区县上传携带省、市、区县三级编码，直辖市区县上传携带省级和区县编码并省略 `cityCode`。更新和删除仅使用记录 ID 及可编辑元数据，不携带行政区字段。

位置标签不再生成或解析。标签工具只管理唯一的 `visited:YYYY-MM-DD` 和去重后的用户标签。这样与后端的精确行政区查询保持一致，也防止编辑操作意外改变归属。替代方案是同时保留位置标签作为兼容字段，但会形成两个可能冲突的数据源，且无法可靠迁移已有空字段记录，因此不采用。

### 将 API 客户端与领域映射分离

API 客户端负责五个 `/api/information/*` 请求、统一响应校验和请求格式：列表、详情和删除使用 JSON，上传与更新使用 `multipart/form-data`。元数据类型同步 `provinceCode`、`cityCode`、`districtCode`、`uploadTime` 等后端字段。

领域加载器负责把列表元数据映射为足迹、验证游玩日期、解析用户标签、解析区县名称以及按需加载详情图片。市级上下文通过本地行政区目录校验 `districtCode` 并取得区县名称；未知区县或无有效游玩日期的记录会被过滤。单条详情失败只标记该记录的图片加载失败，不使整页失败。

### 将信息面板改为能力驱动的通用组件

现有面板改为接收行政区上下文并据此显示操作。市级面板隐藏全部创建入口和空状态中的新增按钮，但保留编辑、删除；区县面板显示创建、编辑和删除。市级卡片额外展示所属区县名称。

创建表单提交前除现有图片、标题和日期校验外，还验证当前上下文为区县。编辑表单从原记录取得可编辑字段，提交时显式排除所有行政区字段。写操作失败保留表单或列表，成功后刷新当前上下文。

### 普通省份与直辖市使用不同的地图选择结果

普通省份地图中的市级区域继续导航到现有县级地图路由；该路由默认显示市级聚合面板，选择区县后切换为区县面板。

北京、上海、天津和重庆的省级地图直接包含区县。地图组件允许这些区县触发选择事件，省级页面在本地保存所选区县并显示区县面板，不请求额外 GeoJSON，也不增加路由。取消选择或离开页面即退出该区县状态。其他已经处于县级的特殊区域保持不可选择。

### 删除后按有效页刷新

删除成功后，如果当前页大于一且删除前当前页只有一条可见记录，则加载上一页；否则刷新当前页。删除失败不清空记录。该规则放在面板状态层而非组件模板中，便于覆盖分页边界测试。

## Risks / Trade-offs

- [后端允许缺少行政区字段，绕过前端可产生无归属记录] → 前端只在类型完整的区县上下文开放上传；安全校验不在本次范围。
- [当前后端存量记录行政区字段为空] → 新查询不会返回这些记录，前端不做标签回退或迁移。
- [直辖市区县选择未写入路由] → 刷新和分享链接不会恢复选择；本次按已确认范围接受该限制。
- [详情接口返回完整 Base64，当前页可能占用较多内存] → 保持现有每页十条和单图失败降级；性能优化留待后续变更。
- [本地行政区目录与后端 `districtCode` 不一致] → 市级列表过滤无法识别的记录，避免在错误区县名下编辑或删除。

## Migration Plan

1. 确认部署环境的 OpenAPI 已包含 `/api/information/*`，并将三级行政区上传字段标记为可选。
2. 发布前端后，新创建记录仅使用结构化行政区字段；旧位置标签不再生成。
3. 行政区字段为空的历史记录保持在后端但不显示；如需恢复，另行执行后端数据迁移。
4. 回滚需要同时恢复兼容 `/api/images/*` 的后端版本或旧接口转发；仅回滚前端无法兼容新接口路径。
