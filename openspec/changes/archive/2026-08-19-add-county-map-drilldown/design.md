## Context

现有全国地图使用离线省级轮廓，省份详情页按省级代码动态导入市级 GeoJSON。新的区县数据不适合随应用构建分发，且当前项目没有后端代理。

## Goals / Non-Goals

**Goals:**

- 为可下钻市级区域添加稳定、可刷新和可分享的县级路由。
- 通过可替换的前端数据适配层控制远程数据的加载、校验、取消、超时和会话缓存。
- 保持现有 SVG 地图的视觉和键盘可访问性。

**Non-Goals:**

- 不进入街道或乡镇级地图。
- 不把县级 GeoJSON 写入静态资源、构建产物或新增后端服务。
- 不为不可继续下钻的特殊地区伪造更低层级地图。

## Decisions

### 独立县级路由

使用 `/province/:province/city/:cityCode`。市级编码由本地行政区目录解析并校验其所属省份，再决定是否允许请求。相比依赖临时组件状态，路由可在刷新和分享链接后恢复页面语义。

### 可替换的公开数据适配层

默认使用 `https://geo.datav.aliyun.com/areas_v3/bound/{cityCode}_full.json`，支持以 `VITE_COUNTY_MAP_API_BASE` 覆盖。加载器对 GeoJSON 的集合、要素、名称、编码和几何类型做运行时校验，成功结果按市级编码缓存。相比在组件中直接 fetch，此边界便于测试和后续迁移至自建服务。

### 请求生命周期

页面监听路由变化并将 `AbortSignal` 传给加载器；加载器另设十秒超时控制器。调用方主动取消维持 `AbortError`，网络、超时和格式错误归一为可重试错误。无需重试次数策略：由用户显式触发重新加载。

### 可访问的标签密度策略

地图路径始终渲染；县级页基于投影后的区域宽高和文字尺寸决定标签可见性。隐藏的标签仍通过可聚焦路径、`aria-label` 和 SVG `title` 提供名称。市级页仍使用完整标签以保留原有浏览体验。

## Risks / Trade-offs

- [公共服务可用性或跨域策略变化] → 接口地址可配置；异常状态保留重试和返回导航。
- [远程边界坐标或属性格式变化] → 在适配层拒绝无效数据，避免渲染异常。
- [县区密集导致名称不可读] → 只隐藏文字，不移除边界或可访问名称。

## Migration Plan

1. 发布前配置可选的 `VITE_COUNTY_MAP_API_BASE`；未配置时使用 DataV 默认地址。
2. 部署前执行单元测试与生产构建，并手动打开普通省份城市及直辖市区域确认导航行为。
3. 若公共接口不可用，配置该环境变量指向兼容 GeoJSON 服务即可回退，无需重新打包县级数据。
