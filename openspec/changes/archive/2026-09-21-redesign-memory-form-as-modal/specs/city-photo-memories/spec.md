## MODIFIED Requirements

### Requirement: 创建带照片的区县足迹

系统 MUST 仅允许用户在已选择的区县状态创建足迹。创建入口 MUST 打开居中模态弹窗承载表单，弹窗 MUST 可通过关闭按钮、`ESC` 键和点击遮罩关闭，MUST 在打开期间把焦点限制在弹窗内，并在关闭后把焦点归还到打开它的入口。

创建表单 MUST 要求选择一张不超过 50MB 的 JPEG 或 PNG、填写标题和有效游玩日期；感受与用户标签为可选项。照片 MUST 同时支持拖拽投放和点选文件两种选择方式；选中后 MUST 显示该照片的缩略图预览、文件名与重新选择入口。用户标签 MUST 以可独立移除的标签项呈现，并 MUST 提供一组内置固定常用词供点选添加。

普通省份的区县上传 MUST 携带 `provinceCode`、`cityCode` 和 `districtCode`，直辖市区县上传 MUST 携带 `provinceCode` 和 `districtCode` 并省略 `cityCode`。前端文件类型与大小校验不得替代后端内容校验。

#### Scenario: 在普通省份区县创建足迹

- **WHEN** 用户在四川省凉山彝族自治州木里藏族自治县提交有效 JPEG/PNG、标题和游玩日期
- **THEN** 上传请求包含对应的省、市、区县编码以及 `visited:YYYY-MM-DD` 标签

#### Scenario: 在直辖市区县创建足迹

- **WHEN** 用户在北京市东城区提交有效创建表单
- **THEN** 上传请求包含北京省级编码和东城区县级编码且不包含 `cityCode`

#### Scenario: 创建时选择无效文件

- **WHEN** 用户通过点选或拖拽提供非 JPEG/PNG 或超过 50MB 的文件
- **THEN** 页面显示校验错误且不发送创建请求

#### Scenario: 未选择区县时尝试创建

- **WHEN** 用户位于省级或市级上下文
- **THEN** 页面不提供创建入口且不发送上传请求

#### Scenario: 打开创建弹窗

- **WHEN** 用户在区县上下文点击创建入口
- **THEN** 系统打开居中模态弹窗并显示空白创建表单
- **AND** 弹窗打开期间键盘焦点不离开弹窗

#### Scenario: 关闭创建弹窗

- **WHEN** 用户点击关闭按钮、按下 `ESC` 键或点击弹窗外遮罩
- **THEN** 弹窗关闭且不发送任何请求
- **AND** 焦点返回到打开该弹窗的创建入口

#### Scenario: 拖拽投放照片

- **WHEN** 用户把一张 JPEG 或 PNG 拖入照片投放区并释放
- **THEN** 系统接受该文件并显示其缩略图预览与文件名

#### Scenario: 点选常用词添加标签

- **WHEN** 用户点击一个内置常用词
- **THEN** 该词作为可独立移除的标签项加入标签字段

#### Scenario: 移除已添加的标签

- **WHEN** 用户点击某个标签项的移除按钮
- **THEN** 该标签项从表单中消失且不影响其他标签项

#### Scenario: 创建提交失败

- **WHEN** 上传请求失败
- **THEN** 系统保留弹窗内已填写的全部内容并显示错误信息

### Requirement: 编辑城市足迹

系统 MUST 允许用户在市级和区县级信息列表中编辑足迹的标题、游玩日期、感受和用户标签。编辑入口 MUST 打开与创建共用的居中模态弹窗，弹窗 MUST 预先填入该足迹的当前值，并 MUST 遵循与创建弹窗相同的关闭方式与焦点行为。编辑表单 MUST NOT 提供照片选择或替换能力，更新请求 MUST 使用原记录标识且不得包含文件或修改 `provinceCode`、`cityCode`、`districtCode`；图片只能通过独立图片集管理。

#### Scenario: 仅编辑文字元数据

- **WHEN** 用户修改标题、游玩日期、感受或用户标签并提交
- **THEN** 系统仅更新元数据且不提交文件或任何行政区字段

#### Scenario: 替换足迹照片

- **WHEN** 用户需要替换已有足迹照片
- **THEN** 元数据编辑表单不提供照片替换，系统引导用户在独立图片集内先新增或删除图片且保持原行政区归属

#### Scenario: 用户需要修改图片

- **WHEN** 用户要新增或删除已有足迹图片
- **THEN** 页面引导用户打开独立图片集管理，不在元数据编辑表单中替换照片

#### Scenario: 编辑失败

- **WHEN** 更新请求失败
- **THEN** 系统保留编辑表单内容并显示错误信息

#### Scenario: 打开编辑弹窗

- **WHEN** 用户点击某条足迹的编辑入口
- **THEN** 系统打开模态弹窗并预填该足迹的标题、游玩日期、感受与用户标签
- **AND** 弹窗内不出现照片投放区或任何照片选择控件

#### Scenario: 编辑弹窗中移除标签

- **WHEN** 用户在编辑弹窗中移除一个已有标签项并提交
- **THEN** 更新请求的标签不再包含该词且保留 `visited:YYYY-MM-DD` 受管理标签

### Requirement: 删除城市足迹

系统 MUST 允许用户在市级和区县级信息列表中通过明确标记为“删除足迹”的操作删除整条足迹。确认界面 MUST 以模态弹窗呈现，展示足迹标题、当前图片数量和不可恢复提示，并 MUST 与“删除所选图片”操作保持视觉和文案区分。确认弹窗 MUST 支持取消，且取消后 MUST 把焦点归还到触发删除的按钮。删除成功后系统 MUST 刷新列表；删除当前页最后一条记录后 MUST 返回上一有效页。删除失败时 MUST 保留当前记录并显示错误信息。

#### Scenario: 确认删除

- **WHEN** 用户点击“删除足迹”并确认包含标题与图片数量的不可恢复提示
- **THEN** 系统请求删除整条足迹及其全部图片并刷新当前行政区列表

#### Scenario: 删除操作与图片删除区分

- **WHEN** 用户在足迹卡片和图片管理弹窗中查看可用操作
- **THEN** 卡片显示“删除足迹”，图片管理弹窗显示“删除所选图片”，两者不得使用含糊的同一文案

#### Scenario: 删除分页末项

- **WHEN** 用户删除非首页的当前页最后一条足迹
- **THEN** 系统加载上一页并展示其记录

#### Scenario: 删除失败

- **WHEN** 删除足迹请求失败
- **THEN** 当前列表保留被删除记录并显示错误信息

#### Scenario: 取消删除

- **WHEN** 用户取消删除足迹确认
- **THEN** 系统不发送删除请求且列表保持不变
- **AND** 焦点返回到触发删除的“删除足迹”按钮
