## 为什么

现有行政区页面只能浏览边界，无法留下旅行照片和感受。后端已经提供图片的上传、查询、更新与删除接口，前端需要将这些通用图片记录按市级与区县级行政区组织为可维护的个人足迹。

## 变更内容

- 在市级行政区页面展示当前行政区的个人照片足迹，并支持分页浏览。
- 点击区县边界后切换到该区县的独立足迹上下文。
- 新增带照片的足迹创建、编辑和删除流程；创建时必须上传照片，编辑时可选替换照片。
- 使用统一标签协议将城市编码、游玩日期和自定义标签写入现有图片接口，不改动后端接口。
- 新增统一的前端图片 API 客户端、类型定义和开发环境代理配置。
- 为标签协议、接口请求和城市足迹页面状态补充自动化测试。

## 能力

### 新增能力

- `city-photo-memories`：在市级与区县级行政区页面管理带照片、游玩日期、感受和标签的个人足迹。

### 修改能力

- 无。

## 影响

- 受影响页面：[CountyDirectory.vue](../../../src/views/CountyDirectory.vue) 及全局样式。
- 新增前端 API 模块、标签解析工具、足迹组件及其测试。
- Vite 开发服务器将代理 `/api` 请求至 `http://localhost:8081`。
- 使用现有后端图片接口：`/api/images/upload`、`/api/images/list`、`/api/images/detail`、`/api/images/update`、`/api/images/delete`；不引入新的后端依赖或接口变更。
