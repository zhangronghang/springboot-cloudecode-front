## Context

当前详情页从 `Province` 目录读取下级行政区名称并以网格表格渲染；全国页已使用离线 SVG 省级边界。此次变更需要为详情页引入按省份选择的市级边界数据，详见 proposal.md 与 `province-city-map` 规格。

## Goals / Non-Goals

**Goals:**

- 详情页渲染单个省份的市级边界与名称。
- 数据按需加载且随构建产物离线提供。
- 直辖市和暂无边界数据的地区具备可读降级状态。

**Non-Goals:**

- 不提供市级点击后的区县钻取。
- 不引入在线地图瓦片、定位、搜索或地图编辑能力。

## Decisions

### 静态 GeoJSON 按省分包

将市级边界以每省一份 GeoJSON 静态资源随项目发布，并用省级行政区代码建立索引。详情页通过动态导入或静态资源 URL 只载入当前省份数据，避免一次加载全国市级边界。

备选方案是运行时请求第三方地图 API；该方案不满足离线约束。另一方案是把全部边界内联到单个脚本；会增加首页载荷，因此不采用。

### 复用 SVG 渲染层

将 GeoJSON 转换为 SVG path，并使用 path 的边界框定位名称标注；这与现有全国地图一致，可保持键盘可访问性和当前视觉系统。地图投影和路径转换封装在独立数据/渲染模块，详情视图仅负责路由状态和页面布局。

备选方案是引入完整地图图表库；当前交互仅需边界与名称，额外图表运行时没有必要。

### 以省份代码匹配数据

路由仍使用中文省份短名，但先通过现有省份目录解析为标准六码行政区代码，再选择对应边界资源。地理特征的名称和行政区代码用于匹配显示标签，名称缺失时使用已有城市目录作后备显示。

## Risks / Trade-offs

- [市级 GeoJSON 体积较大] → 每省独立资源并延迟加载；构建时保留压缩。
- [小区域名称互相遮挡] → 依据轮廓边界动态缩放文字；无法清晰放置时显示简写或在地图旁提供小型图例。
- [直辖市行政层级不同] → 使用同一“下级行政区”语义渲染区县边界，不强制将其称为城市。
- [部分地区缺少公开市级边界] → 展示明确的不可用状态并保留返回操作。

## Migration Plan

1. 新增市级边界资源与省份代码索引。
2. 实现省级地图加载和 SVG 渲染组件。
3. 用地图视图替换详情页的表格；保留无数据回退。
4. 构建和测试通过后发布；如发现资源问题，可回退到上一个已发布版本。
